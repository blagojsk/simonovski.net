# simonovski.net — repository rules

Rules and guidelines only. This is Blagoj Simonovski's personal résumé site: static HTML and CSS, no build step.

## Never, at all

- **Never add a build step, framework or npm dependency.** Static `index.html`, `style.css` and `script.js` only.
- **Never commit personal documents or secrets.** `.gitignore` excludes `*.pdf` (except the résumé), office files and
  `.env*`; keep it that way.
- **Never let the PDF drift from the page.** `Blagoj_Simonovski_Resume.pdf` is generated by `./make-pdf.sh` from
  `index.html` and `style.css`; never edit or hand-replace it.

## Never, unless explicitly asked

- Change `CNAME` (the domain) or deploy: the live site is production, and every production action needs the
  operator's go-ahead for that action.
- Work on `master`. Branch first; merge only when asked, and asked again for the next merge.
- Push, publish or mark a draft PR ready.

## Working rules

- **Commits and PRs carry no AI attribution**: no Co-Authored-By lines, no "generated with" footers. Conventional
  commit messages.
- **Long builds and test gates run in the background**, with output in a log file, and their exit code is read.
  Never two runs in one tree.
- **Enable the pre-commit hook once per clone**: `git config core.hooksPath .githooks`. It regenerates the PDF when
  `index.html` or `style.css` is staged and adds it to the commit.
- **Before a commit:** open `index.html` in a browser at roughly 375px, 768px and 1280px and read it; follow every
  link and asset reference; confirm the PDF was regenerated and shows the three embedded web fonts.

## Delegation

**Spend the expensive models on thinking, not typing.** The model the user picked for the session is the
orchestrator. It plans, decides what it does itself and what it hands down, and for each handed-down task picks the
**cheapest worker that will do the job well**. A stronger worker has to be earned by real ambiguity, a design call or
an unfamiliar subsystem; it is never picked by default.

| Orchestrator | Does itself | Hands down |
|---|---|---|
| **Fable** | Plans and orchestrates; does **not** implement | **Opus** only where a task still needs judgement mid-flight; **Sonnet** for anything the plan fully specifies; **Haiku** for mechanical passes |
| **Opus** | Plans, then implements only the parts that need its own judgement | **Sonnet** for specified work; **Haiku** for mechanical passes |
| **Sonnet** | Implements | **Haiku** for mechanical passes |
| **Haiku** | Mechanical, fully specified edits | — |

A delegated task carries what the delegate cannot infer:
- the files involved;
- the rule it must not break;
- the branch it works on;
- how the result is verified.

Whoever plans still reads the code, and reviews the result before it is committed or deployed.
